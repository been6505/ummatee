# แผนพัฒนาหน้า Admin เป็นระบบภายในสำหรับพนักงานอุมมะตี

เอกสารนี้ประเมินจากโค้ดจริงในโปรเจกต์ ณ วันที่เขียน ไม่ใช่การคาดเดา

---

## 1. สถานะจริงวันนี้ — อะไรมีแล้ว อะไรยังไม่มี

มีหน้า admin อยู่แล้ว **27 หน้า** และ Firestore collection **26 ชุด** ของที่ขอมาบางส่วนทำเสร็จแล้ว

| # | สิ่งที่ขอ | สถานะ | รายละเอียด |
|---|---|---|---|
| 1 | Database สำหรับยิงแอด | ❌ ยังไม่มี | มีข้อมูลติดต่อกระจายใน `donations`/`orders`/`volunteerRegs` แต่ไม่มีระบบรวมเป็นกลุ่มเป้าหมาย |
| 2 | วางแผน campaign บริจาค | 🟡 บางส่วน | มี `donations`, `AdminDonations`, บอร์ด Trello — แต่ไม่มี "campaign" เป็นก้อนเดียวที่มีเป้า/งบ/ช่วงเวลา |
| 3 | วางแผน event | 🟡 บางส่วน | มีปฏิทิน, ลงทะเบียน Iftar, เช็คอิน QR — แต่เป็นงานเฉพาะกิจ ไม่ใช่ระบบ event ทั่วไป |
| 4 | วางแผนคอนเทนต์ (ข้อความ/รูป/วิดีโอ/live) | 🟢 เกือบครบ | `AdminCalendar` + `contentPosts` + อัปโหลด Cloudinary + โพสต์จริงผ่าน content-hub — ขาดแค่ "live" เป็นชนิดคอนเทนต์ |
| 5 | ขายสินค้า + คลัง + แจ้ง LINE เมื่อมีออเดอร์ | ✅ **เสร็จแล้ว** | `AdminShop`, `AdminInventory`, `stockMovements`, `AdminShopOrders`, `AdminShopSales` + แจ้งเตือน LINE/อีเมลตอนมีออเดอร์และตอนสต็อกใกล้หมด (วิ่งผ่าน Apps Script ที่ deploy แล้ว) |
| 6 | Co ร้านค้า + รายชื่อร้านร่วม campaign | 🟡 บางส่วน | มี `partnerOrganizations` (หน้า `AdminPartners`) แต่ยังไม่ผูกกับ campaign |
| 7 | รวมแชททุกแพลตฟอร์ม | 🔴 **ยังไม่ทำงานจริง** | โค้ด webhook LINE/FB/IG เขียนครบใน `functions/index.js` แต่ **ยัง deploy ไม่ได้** (ทดสอบแล้วตอบ HTTP 404) ตอนนี้ `chats` รับได้แค่จากวิดเจ็ตแชทบนเว็บ |
| 8 | เข้าใช้ผ่าน Gmail | ✅ **เสร็จแล้ว** | Google Sign-In ในหน้าล็อกอิน (เหลือเปิด provider ใน Firebase Console) |
| 9 | Video call + Live ลง FB/TikTok/YouTube | ❌ ยังไม่มี | ติดข้อจำกัดโครงสร้างพื้นฐาน — ดูหัวข้อ 4 |

**สรุป: ข้อ 5 และ 8 เสร็จแล้ว, ข้อ 4 เกือบครบ, ที่เหลือต้องทำ**

## 2. จุดตัดสินใจที่ต้องเคลียร์ก่อน — เรื่องเซิร์ฟเวอร์

นี่คือเรื่องที่กำหนดทุกอย่างที่เหลือ

เว็บ ummatee ตอนนี้เป็น **static site** (Firebase Hosting + Firestore แพลน Spark) **ไม่มีเซิร์ฟเวอร์** สิ่งที่ทำไม่ได้เลยบนสถาปัตยกรรมนี้:

- รับ webhook จาก LINE/Facebook/Instagram (ต้องมี endpoint ให้เขายิงเข้า)
- เก็บ OAuth token อย่างปลอดภัย (ต้องมี client_secret ฝั่งเซิร์ฟเวอร์)
- งานตามเวลา (โพสต์ตามกำหนด, รายงานรายเดือน)
- ประมวลผลวิดีโอ/สตรีม

**ของที่มีอยู่แล้วและใช้งานได้:**

| ตัวเลือก | สถานะ | ทำอะไรได้ | ข้อจำกัด |
|---|---|---|---|
| Google Apps Script | ✅ ใช้งานอยู่ | อีเมล, LINE push, เขียน Sheet | รันได้ไม่เกิน 6 นาที, ไม่เหมาะงานหนัก |
| Cloud Functions | ⚠️ เขียนครบ ยัง deploy ไม่ได้ | webhook, OAuth, cron ครบ | **ต้องอัปเกรด Blaze (ผูกบัตร + มัดจำ ฿400)** |
| content-hub (Vercel) | ✅ ใช้งานอยู่ | OAuth 5 แพลตฟอร์ม + โพสต์จริง | เว็บแยก คนละระบบกับ ummatee |
| UmmateeThailand (Next.js/Vercel) | ⚠️ เขียนครบ ยัง deploy ไม่ได้ | **มีเกือบทุกอย่างที่ขอแล้ว** | ต้องตั้ง Neon DB + env vars |

### 💡 ข้อเสนอ: ใช้ UmmateeThailand เป็นฐานของระบบพนักงาน

โปรเจกต์ `UmmateeThailand` (Next.js บน Vercel) **มีของที่ขอไปแล้วเยอะมาก**: บัญชีพนักงาน 4 ระดับ, CRM องค์กรพันธมิตร, แผนที่ความช่วยเหลือ, บอร์ดวางแผน, โพสต์หลายแพลตฟอร์ม, คอมเมนต์, เอนเกจ, audit log, แจ้งเตือน — และ **Vercel ฟรี ไม่ต้องผูกบัตร**

**แบ่งหน้าที่แบบนี้:**
- **Firebase (ummatee) เก็บงานธุรกรรม** — ร้านค้า/คลัง/ออเดอร์/บริจาค/ลงทะเบียน (ทำงานดีอยู่แล้ว ไม่ต้องย้าย)
- **Vercel (UmmateeThailand) เก็บงานปฏิบัติการ** — แชทรวม, campaign, event, คอนเทนต์, ร้านค้าร่วม, ยิงแอด

ทางเลือกอื่นคืออัปเกรด Blaze แล้ว deploy Cloud Functions ที่เขียนไว้แล้ว (เร็วกว่า แต่ต้องผูกบัตร)

## 3. แผนงานแยกตามหัวข้อ

### ข้อ 1 — Database สำหรับยิงแอด
สร้าง `audiences` (กลุ่มเป้าหมาย) + `contacts` (รายบุคคล พร้อมแหล่งที่มาและสถานะความยินยอม) แล้ว export เป็น CSV เข้า Meta/TikTok Ads Manager ได้

⚠️ **ต้องระวัง PDPA:** การนำอีเมล/เบอร์ผู้บริจาคไปทำ Custom Audience ต้องมี**ฐานความยินยอม**ที่ชัดเจน และเงื่อนไขของ Meta เองก็บังคับว่าต้องได้รับความยินยอมก่อน — ต้องเพิ่ม checkbox ขอความยินยอมในฟอร์มบริจาค/สั่งซื้อ และเก็บหลักฐานว่ายินยอมเมื่อไหร่ ไม่ควรดึงข้อมูลเก่าที่ไม่เคยขอไปใช้ ขนาดงาน: **กลาง** (โค้ดไม่ยาก แต่เรื่องความยินยอมต้องทำให้ถูก)

### ข้อ 2 — Campaign บริจาค
`campaigns`: ชื่อ, เป้าเงิน, ยอดปัจจุบัน, ช่วงเวลา, ผู้รับผิดชอบ, ช่องทางที่ใช้, สถานะ — ผูกกับ `donations`, `contentPosts`, ร้านค้าร่วม, การ์ดบอร์ด เพื่อดูภาพรวมแคมเปญเดียวจบ ขนาดงาน: **กลาง**

### ข้อ 3 — Event
`events`: ชื่อ, วันเวลา, สถานที่, งบ, เป้าผู้เข้าร่วม, ลงทะเบียน, เช็คอิน — ยกระบบ Iftar (ที่มีลงทะเบียน+QR เช็คอินอยู่แล้ว) ให้เป็นระบบทั่วไปใช้ซ้ำได้ทุกงาน ขนาดงาน: **กลาง–ใหญ่**

### ข้อ 4 — คอนเทนต์
มีเกือบครบแล้ว เพิ่ม: ชนิด `live` (วันเวลา/แพลตฟอร์ม/ผู้ดำเนินรายการ), สถานะอนุมัติ (ร่าง→รอตรวจ→อนุมัติ→โพสต์), ผูกกับ campaign/event ขนาดงาน: **เล็ก–กลาง**

### ข้อ 5 — ขายสินค้า/คลัง/แจ้ง LINE
✅ **เสร็จแล้ว ไม่ต้องทำอะไรเพิ่ม** (เพิ่งแก้ช่องโหว่ LINE ไปด้วย — ต้องเอา `docs/volunteer-apps-script/Code.gs` ไปวางใน Apps Script ให้เรียบร้อย)

### ข้อ 6 — ร้านค้าร่วม campaign
ขยาย `partnerOrganizations` ให้แยกประเภท "ร้านค้า" + สร้าง `campaignPartners` เชื่อมร้าน↔แคมเปญ (บทบาท, สิ่งที่สนับสนุน, สถานะติดต่อ) + หน้าเว็บสาธารณะแสดงรายชื่อร้านร่วมแคมเปญ ขนาดงาน: **เล็ก–กลาง**

### ข้อ 7 — รวมแชท
โค้ดเขียนครบแล้ว **ติดแค่ที่ deploy** เลือกทางใดทางหนึ่ง:
- deploy Cloud Functions ที่มีอยู่ (ต้อง Blaze) — เร็วสุด โค้ดพร้อม
- ย้าย webhook ไป Vercel (ฟรี) — ต้องเขียนใหม่บ้าง

ข้อจำกัดตามแพลตฟอร์ม: LINE ✅ / Facebook Messenger ✅ / Instagram DM ⚠️ ต้องผ่าน Meta App Review / **TikTok, Threads, X ❌ ไม่มี DM API ให้ใช้** ขนาดงาน: **เล็ก** (ถ้า deploy) หรือ **กลาง** (ถ้าย้าย)

### ข้อ 8 — เข้าใช้ผ่าน Gmail
✅ **เสร็จแล้ว** เหลือเปิด Google provider ใน Firebase Console → Authentication → Sign-in method

### ข้อ 9 — Video call + Live
ดูหัวข้อถัดไป — มีข้อจำกัดที่แก้ด้วยโค้ดไม่ได้

## 4. ข้อจำกัดที่แก้ด้วยการเขียนโค้ดไม่ได้

### Live สดออกหลายแพลตฟอร์มพร้อมกัน (restream)
**ทำบน Vercel/Firebase ไม่ได้เด็ดขาด** — การกระจายสตรีมต้องมีเซิร์ฟเวอร์รับ RTMP แล้วรันโปรแกรมส่งต่อ (ffmpeg) **ต่อเนื่องตลอดเวลาที่ไลฟ์** ซึ่ง serverless ทำไม่ได้ (รับได้แค่ HTTP และตัดการทำงานเมื่อจบ request)

| ทางเลือก | ค่าใช้จ่าย | ข้อดี/ข้อเสีย |
|---|---|---|
| **OBS บนคอมตัวเอง + ปลั๊กอิน multi-output** | **ฟรี** | ถูกสุด ทำได้เลย — แต่ต้องเปิดคอมไว้ตลอดไลฟ์ และเน็ตอัปโหลดต้องแรงพอ (คูณจำนวนปลายทาง) |
| Restream.io / Castr | ~$16–50/เดือน | ง่ายสุด เสถียร มีหน้าจัดการ — เสียเงินรายเดือน |
| VPS + nginx-rtmp เอง | ~$5–12/เดือน | ถูกกว่า SaaS คุมเองได้ — ต้องดูแลเซิร์ฟเวอร์เอง |

**ข้อจำกัดเพิ่มเติมที่ต้องรู้:**
- **TikTok Live ผ่าน RTMP ต้องมีคุณสมบัติก่อน** (ปกติต้องมีผู้ติดตามระดับหนึ่ง) และ TikTok **ไม่เปิด API ให้บุคคลที่สามสั่งไลฟ์ทั่วไป** — อาจต้องไลฟ์จากแอป TikTok แยก
- **อัตราส่วนภาพขัดกัน**: FB/TikTok ใช้ตั้ง 9:16 / YouTube ใช้นอน 16:9 — เครื่องเดียวส่งพร้อมกันให้สวยทั้งคู่ไม่ได้ ต้อง **เข้ารหัส 2 ชุด** (เปลืองซีพียู+แบนด์วิดท์เท่าตัว) หรือยอมให้มีขอบดำ

### Video call
ไม่ต้องสร้างเอง แนะนำ **ฝัง Jitsi Meet** (ฟรี ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องสมัคร) หรือแปะลิงก์ Google Meet ก็พอ — การเขียน WebRTC เองต้องมี signaling + TURN server ซึ่งไม่คุ้มเลย ขนาดงาน: **เล็ก** (ถ้าฝัง Jitsi)

## 5. ลำดับที่แนะนำ

**เก็บของที่ค้างให้จบก่อน (ทำได้ทันที ไม่ต้องตัดสินใจอะไร)**
1. เปิด Google provider ใน Firebase Console → ข้อ 8 ใช้งานได้จริง
2. วางโค้ด `Code.gs` ใหม่ใน Apps Script → ปิดช่องโหว่ LINE + ข้อ 5 สมบูรณ์
3. ตรวจ `/admin/staff` ว่ามีบัญชีแปลกปลอมไหม + เปิด App Check

**ตัดสินใจเรื่องเซิร์ฟเวอร์** — Blaze หรือ Vercel (กำหนดทุกอย่างที่เหลือ)

**เฟส 1 — ของที่คุ้มที่สุดต่อแรง**
4. รวมแชทให้ทำงานจริง (ข้อ 7 — โค้ดพร้อมแล้ว)
5. Campaign + ร้านค้าร่วม (ข้อ 2 + 6 — เกี่ยวกันโดยตรง ทำคู่กันคุ้มกว่า)
6. ฝัง Jitsi สำหรับ video call (ข้อ 9 ครึ่งแรก)

**เฟส 2**
7. ระบบ Event ทั่วไป (ข้อ 3)
8. เพิ่ม live + สถานะอนุมัติในคอนเทนต์ (ข้อ 4)

**เฟส 3 — ต้องเคลียร์เรื่องกฎหมาย/อุปกรณ์ก่อน**
9. Database ยิงแอด (ข้อ 1 — ต้องทำเรื่องความยินยอม PDPA ให้ถูกก่อน)
10. Live หลายแพลตฟอร์ม (ข้อ 9 — ต้องเลือกวิธีและอุปกรณ์ก่อน แนะนำเริ่มจาก OBS ฟรี)
